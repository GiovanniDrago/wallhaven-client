# F-Droid metadata — Gradle/Kotlin recipes

The file is `metadata/<package-id>.yml` in `fdroiddata`. It is YAML, not XML. The
published index is generated by `fdroid update`; never create it by hand.

Use `assets/metadata-gradle.yml` for the default reproducible recipe and replace every
`__PLACEHOLDER__`; the validation script rejects leftovers.

## Descriptive fields

| Field | Rule |
|---|---|
| `Categories` | A YAML list; use the live list from `references/categories.md` |
| `License` | One SPDX identifier, e.g. `GPL-3.0-only` |
| `AuthorName` | Public author name or pseudonym |
| `SourceCode` | Human-friendly source URL |
| `IssueTracker` | Issue tracker URL |
| `Changelog` | Release/changelog URL |
| `RepoType` | `git` |
| `Repo` | Public HTTPS clone URL, normally ending in `.git` |

Do **not** add `Summary`, `Description`, `Name`, icons, screenshots, or changelog text.
F-Droid reads them from the upstream fastlane tree.

## Gradle build block

```yaml
Builds:
  - versionName: 0.5.0
    versionCode: 6
    commit: 0123456789abcdef0123456789abcdef01234567
    subdir: app
    gradle:
      - yes
    gradleprops:
      - fdroid
    binary: https://github.com/example/app/releases/download/personal-App-%v-%c/App-%v-%c.apk
```

- `subdir`: the directory containing the module `build.gradle.kts` (`app` in a standard
  Android project).
- `gradle: - yes`: F-Droid runs the buildserver's `gradle assembleRelease`. The F-Droid
  scanner removes `gradlew`, `gradlew.bat`, and `gradle-wrapper.jar` from the checkout, so
  do **not** use `./gradlew` in the metadata.
- `gradleprops: - fdroid`: passes `-Pfdroid` so the release keystore is not required.
- `SOURCE_DATE_EPOCH` is set automatically by `fdroidserver` for the build. Do not rely on
  an `export` in `prebuild` for the main Gradle command.
- `binary`: only in reproducible mode; the URL uses `%v` and `%c`.
- If the module has a product flavor, use `gradle: - <flavor>` and adjust the APK path.

The buildserver's Gradle version must support the project's AGP. If it does not, the
build log will say so; do not hide the error with `novcheck`. A manual build is possible
when the `gradle` shortcut cannot express the task, but it must use the system `gradle`
binary, not `./gradlew`:

```yaml
    build:
      - gradle assembleRelease -Pfdroid
    output: app/build/outputs/apk/release/app-release-unsigned.apk
```

## Signing for F-Droid

F-Droid must build without the developer's keystore. The app should support a property:

```kotlin
if (!project.hasProperty("fdroid")) {
    signingConfigs {
        create("release") {
            storeFile = file("../release.keystore")
            storePassword = System.getenv("KEYSTORE_PASSWORD")
            keyAlias = "release"
            keyPassword = System.getenv("KEYSTORE_PASSWORD")
        }
    }
}

android {
    buildTypes {
        release {
            signingConfig = if (project.hasProperty("fdroid")) {
                null
            } else {
                signingConfigs.getByName("release")
            }
        }
    }
}
```

Without this, F-Droid's `assembleRelease` fails because `release.keystore` is not present.
Do not add the keystore to the repository or to the metadata.

## Version and update checks

```yaml
AutoUpdateMode: Version
UpdateCheckMode: Tags personal-WallhavenClient-.*
UpdateCheckData: app/build.gradle.kts|versionCode\s*=\s*(\d+)|.|versionName\s*=\s*"([^"]+)"
CurrentVersion: 0.5.0
CurrentVersionCode: 6
```

- `UpdateCheckMode: Tags` reads the build file at every matching tag and picks the highest
  `versionCode`.
- `UpdateCheckData` paths are relative to the repository root.
- The regex must match the exact syntax in the build file. If the project uses
  `versionCode = 6` with spaces, `versionCode\s*=\s*(\d+)` works.
- If the version is computed by Gradle, F-Droid cannot evaluate it. Move it to a literal
  in the build file or use another `UpdateCheckData` source.
- `versionCode` must increase on every release. A CI run number in the tag is not a
  substitute: F-Droid reads the build file, not the tag suffix.

## Reproducible tag and asset names

The tag and asset must be reconstructible from `%v` and `%c`:

```text
tag:   personal-WallhavenClient-0.5.0-6
asset: WallhavenClient-0.5.0-6.apk
```

```yaml
binary: https://github.com/GiovanniDrago/wallhaven-client/releases/download/personal-WallhavenClient-%v-%c/WallhavenClient-%v-%c.apk
```

Do not use `GITHUB_RUN_NUMBER` in either name. If the current workflow does, change it
before enabling `binary:`. See `references/reproducibility.md`.

## New vs update

For `new`:

1. create `metadata/<package-id>.yml`;
2. fill descriptive fields and the build block;
3. run the validation loop.

For `update`:

1. read the current file from `fdroiddata` `master`;
2. preserve descriptive fields and maintainer notes;
3. replace the old `Builds` list with the new release;
4. update `CurrentVersion` and `CurrentVersionCode`;
5. keep `AutoUpdateMode`, `UpdateCheckMode`, and `UpdateCheckData` unless the release
   process changed;
6. do not add images, descriptions, or disabled versions.

If the package ID changed, treat it as a new app.

## Gotchas

- `versionCode` must be strictly greater than the previous release.
- The release tag must point to the commit that contains that `versionCode`.
- `subdir` is the module directory containing `build.gradle.kts` (`app` in a standard
  Android project). The project-level `settings.gradle.kts` is found in the parent.
- F-Droid removes the Gradle wrapper files during scanning. Use the `gradle:` shortcut or
  the system `gradle` binary, not `./gradlew`.
- The buildserver's Gradle version must support the project's AGP. Check the build log;
  do not hide a version mismatch.
- `-Pfdroid` must correspond to a real `project.hasProperty("fdroid")` branch.
- `binary:` is only valid when the tag and asset names are stable and the build is
  reproducible. Do not fake it.
- `AllowedAPKSigningKeys` is the lowercase SHA-256 of the signing certificate, not the
  APK checksum.
- Add `dependenciesInfo { includeInApk = false; includeInBundle = false }` to avoid the
  Gradle dependency-metadata scanner error.
- For deterministic archives, set `isPreserveFileTimestamps = false` and
  `isReproducibleFileOrder = true` on `AbstractArchiveTask`.
- Fastlane changelogs for a single APK use `<versionCode>.txt`; `default.txt` is a safe
  fallback.
- Run `fdroid rewritemeta` and apply its exact diff instead of guessing line wrapping.
